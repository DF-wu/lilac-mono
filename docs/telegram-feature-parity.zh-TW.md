# Telegram Feature Parity

語言：[`English（主要／規範版本）`](./telegram-feature-parity.md) · [`繁體中文（翻譯）`](./telegram-feature-parity.zh-TW.md)

本文件比較 fork 自有的 Telegram surface（`apps/core/src/surface/telegram/`）與 upstream 的 Discord surface（`apps/core/src/surface/discord/`）。對於每一項 Discord 具備、而 Telegram 缺少或實作方式不同的能力，本文記錄其現況、差異存在的原因，以及要補齊需要改動什麼。另外也列出 Telegram 有而 Discord 沒有的能力。

比較基準是以 fork PR [#75](https://github.com/DF-wu/lilac-mono/pull/75) 合併的 Telegram request router 重寫（`refactor/telegram-upstream-alignment`，merge commit `8e134266`，2026-10-05），該重寫讓 Telegram router 的結構對齊 upstream 的 Discord router。以下每一項主張都在該 commit 重新對照程式碼核對過；檔案路徑相對於 repository 根目錄，Telegram 或 Discord 欄位中沒有目錄前綴的路徑位於該 surface 自己的目錄下。

> [!IMPORTANT]
> 這是維護文件，不是 roadmap。當某一列的能力被實作、在 upstream 以平台中立的形式落地，或被決定為 non-goal 時，必須更新或移除該列。「尚未實作」代表可行，不代表已核准：在計畫明定之前它不是工作項目。

## 差異分類方式

| 分類                  | 意義                                                                                                                                                |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bot API 限制          | Telegram Bot API 做不到。本 repository 內沒有任何改動能補齊；若有近似做法，該列會說明                                                               |
| 刻意的 non-goal       | 已決定不做，該列記錄理由                                                                                                                            |
| 尚未實作              | 可以在 fork 自有模組內完成（`apps/core/src/surface/telegram/`、`packages/utils/core-config/telegram-*.ts`），不需改動 upstream contract；只是還沒做 |
| Upstream contract gap | 某個共用或 upstream 檔案把 Discord 寫死，Telegram 實作前需要先改 contract。該列會指出檔案                                                           |

## Router 重寫後已對齊的部分

Telegram router（`telegram-request-router.ts`、`telegram-request-router-composition.ts`、`telegram-request-router-publish.ts`）現在與 `discord-request-router.ts` 結構相同，並且原封不動地 import `apps/core/src/surface/discord/discord-request-router/` 下的共用 helpers（這些檔案沒有 fork 修改）。以下項目已不再是差異：

| 能力                                             | Telegram 實作                                                                                                                                                                                                                                                                                                                     | 與 Discord 共用                                                                            |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Active request 追蹤                              | `startTelegramRequestRouter` 開三個 bus subscription：`evt.request` lifecycle 維持每個 session 一個 active request，`evt.surface` 記錄該 request 的 bot output message ids，`evt.adapter` 分派 inbound messages                                                                                                                                   | 與 Discord router 相同的拓樸                                                                  |
| Session modes                                  | `describeRouting` 透過 `getSessionMode`、`resolveSessionGateEnabled`、`resolveSessionModelOverride`、`resolveSessionConfigId` 解析 mode、gate 旗標、model override 與 config id；DM 永遠是 `active` 且不經 gate（`handleActiveDm`）                                                                                                                  | `discord-request-router/common.ts`、`surface.router.*` 設定                                |
| Debounce 批次                                    | `bufferActiveChannelMessage` 將 active mode 的一般訊息緩衝 `surface.router.activeDebounceMs`；`flushDebounce` 透過 `composeTelegramMessages({ batch })` 把所有緩衝訊息組成一個 `prompt`                                                                                                                                                               | 同一個設定鍵；composition 是 Telegram 專屬，因為 history 來自 local index                              |
| LLM gate                                       | `shouldForwardByGate` 是預設的評估器（`routerGate` 輸入是測試接縫）。`evaluateActiveBatchGate` 對 active mode 批次把關、失敗時 fail closed；`passesDirectReplyGate` 處理「回覆 bot 同時 @ 別人」的歧義、失敗時 fail open                                                                                                                                                    | `discord-request-router/gate.ts`、`context.ts`                                           |
| Steer、interrupt、follow-up、fork、buffered prompt | `routeWhileActive` 交給 `decideActiveRequestRoute` 決定；steer 與 interrupt 先透過 `publishTelegramOutputReanchor` 發出 `cmd.surface.output.reanchor`                                                                                                                                                                                      | `discord-request-router/decisions.ts`                                                   |
| 指令前綴                                           | `!model:`（`parseLeadingModelOverride`）、`!continue`（`parseLeadingContinueDirective`）、`!interrupt`（`parseSteerDirectiveMode`）；`directiveTransform` 在模型看到文字前把它們剝除                                                                                                                                                                  | `discord-request-router/common.ts`                                                      |
| Mention mode 的待處理回覆                            | 沒有 mention 的 active output 回覆會先排隊（`enqueuePendingMentionReply`），在來源 request 結束時合成一個 prompt（`flushPendingMentionRepliesAsPrompt`），或在 steer 之後作為 follow-up 送出（`flushPendingMentionRepliesAsFollowUp`）；批次以 session 加來源 request 為鍵（`pendingReplyKey`），並在 prompt 發布前一直留在記憶體隊列中，因此 flush 失敗時它們會保留在隊列而不是被丟棄，較新的 active request 也不會覆蓋它們 | Telegram 本地實作，對應 `discord-request-router/pending-batch.ts`                              |
| Custom commands                                | `commandMetadata` 在 `routeAdapterMessage` 的 mode 分派之前執行，因此 `/lilac:<name>` 或 `/lilac_<name>` 在 mention mode 下不需 mention 即可使用                                                                                                                                                                                                    | Discord 使用 slash interactions（`discord-command-projection.ts`）                          |
| Request 發布                                     | `publishTelegramRequest` 發出帶有 `authenticatedOrigin`、`triggerType`、`chainMessageIds`、`participantUserIds`、`sessionMode`、`sessionConfigId` 與 `request_client: "telegram"` headers 的 `cmd.request.message`                                                                                                                         | 與 `discord-request-router/publish.ts` 相同的 envelope                                      |
| Reply-wait 抑制                                  | `shouldSuppressAdapterEvent` 讓 `waitForReply` 在 routing 前保留訊息；hook 失敗會成為 routing 失敗，讓該 adapter 事件被 park（`park-pending`）：它會留在 Redis pending-entry list 中，不被 routing，也不在自動 reclamation 範圍內                                                                                                                                        | 相同的 hook 形狀；Discord router 則記錄 `router suppression hook failed; proceeding` 並 fail open |

### Ingress、安全與設定

| Tool-server safety mode | agent runner 對每個 client 都會解析 `surface.router.sessionModes[<id>].safetyMode`（`apps/core/src/surface/bridge/bus-agent-runner.ts` 的 `resolveSessionSafetyMode`），並把它放進發出的 Level 2 control capability；tool server 另外會為沒有 capability 的 request 重新推導 mode，但只處理 Discord（`apps/core/src/tool-server/create-tool-server.ts` 的 `resolveSafetyMode` 與 `create-core-runtime.ts` 的 `resolveServerSafetyMode` hook） | 主要路徑與 Discord 相同：capability 帶著 session 的 mode，`telegramSurfaceProtocol.resolveExternalSafetyMode` 對已驗證的 ingress 會尊重它。只有無 capability 的 fallback 不同：沒有 control capability 的 Telegram request 會解析為 `restricted` | 防禦性 fallback 中的 upstream contract gap（兩個檔案都是 upstream）；一般的 Telegram run 不受影響 | 在 fallback 加入 `telegram` 分支，呼叫 `resolveSessionSafetyMode(config, sessionId)` 並以 topic 所屬 chat 作為 `parentChannelId`，或把 fallback 改成平台中立 |
| Token 來源              | `surface.discord.tokenEnv`（預設 `DISCORD_TOKEN`）                                                                                                                                                                                                                                                                                                                                                                                            | `surface.telegram.token` 直接寫在 `core-config.yaml`；`tokenEnv` 會被拒絕並給出遷移訊息（`packages/utils/core-config/telegram-surface.ts`，commit `4aa6f846`）                                                                                   | 刻意的 non-goal                                                                                   | 若要翻案：把 `tokenEnv` 加回 schema，在 `telegram-runtime.ts` 解析，並在 Compose 注入                                                                        |

## 未使用的 Telegram 平台功能

Discord 沒有對應物，因此這些是 Telegram 端的取捨，不是 parity 差異。

| 功能              | 現況                                                                                          | 原因                                                                                                       | 需要補什麼                                                                                                             |
| ----------------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Webhook ingress   | 只有 long polling（`telegram-adapter.ts` 的 `bot.start()`）                                   | 刻意的 non-goal：polling 不需要公開的 HTTPS endpoint、可在 NAT 後運作；另一個 poller 會以 fatal `409` 浮現 | `setWebhook` 加上帶 secret-token 驗證的 HTTP route；屬於 `scripts/architecture/README.md` 規範下的 trust-boundary 變更 |
| Inline queries    | 未處理                                                                                        | 尚未實作                                                                                                   | 在 `allowed_updates` 註冊 `inline_query` 並以 `answerInlineQuery` 回應；結果需要自己的 session model                   |
| Business accounts | 未處理                                                                                        | 尚未實作                                                                                                   | `business_connection` 與 `business_message` updates，加上支援 business 的 allowlist                                    |
| 語音與影片轉錄    | Audio、video 與 voice 退化為 `[telegram_attachment …]` markers（`telegram-inbound-media.ts`） | 尚未實作；speech-to-text provider 是新的 dependency，必須先獲得核准                                        | 在 inbound media pipeline 加入轉錄步驟                                                                                 |

## Telegram 具備而 Discord 缺少的能力

| 能力                               | Telegram                                                                                                                                                                                      | Discord                                                                                                           |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 持久化的 ingress outbox            | 每個 update 在發布前先寫入 `telegram_ingress_outbox`，重啟後由舊到新重播（`telegram-ingress.ts`、`store/telegram-surface-store.ts`、`telegram-adapter.ts` 的 `scheduleIngressReplay`）        | 沒有 outbox；gateway events 直接發布                                                                              |
| Per-user allowlist                 | `allowedUserIds` 管制已允許聊天室內的 principal（`telegram-guards.ts`）；`allowedChatIds` fail closed                                                                                         | 只有 `allowedGuildIds` 與 `allowedChannelIds`                                                                     |
| Polling supervisor                 | `supervisePolling` 把非預期的結束轉成紅色的 `telegram.ready` 檢查，並把 `401` 與 `409` 歸為 fatal（`isFatalTelegramPollingExit`）                                                             | discord.js 的重連處理；沒有 fatal 分類                                                                            |
| Forum topics 作為 sessions         | `<chat_id>:<topic_id>` session ids 讓 `surface.router.sessionModes` 可以鎖定單一 topic（`telegram-ids.ts`）                                                                                   | Thread 也是 session，但 id 中沒有 forum-topic 的區別                                                              |
| 受 byte 預算管制的 inbound media   | Adapter 實作 `SurfaceAttachmentResolver`（`apps/core/src/surface/adapter.ts`）；media 從 `file_id` 解析、嗅探、依每個附件與每個 request 設上限，寫入 BlobStore（`telegram-inbound-media.ts`） | 附件以 CDN URL resources 傳遞                                                                                     |
| Workflow 卡片的即時 allowlist 複檢 | `createTelegramWorkflowTargetAuthorizer`（`telegram-surface-runtime.ts`）在每次進度卡片的 send、edit、recreation 之前，以及到期排程觸發之前，重新讀取 `allowedChatIds`                        | 沒有 per-send 的授權器                                                                                            |
| 自架 Bot API                       | `apiRoot` 讓 client 指向本地 Bot API server                                                                                                                                                   | 不適用                                                                                                            |
| HTML 退回純文字                    | `output/telegram-output-stream.ts` 的 `withFallbacks` 在 Telegram 拒絕 entities 時，去掉 `parse_mode` 重送                                                                                    | 不適用                                                                                                            |
| Command menu 容量                  | `setMyCommands` 每次連線最多發布 `TELEGRAM_MAX_MENU_COMMANDS = 100` 個 aliases                                                                                                                | `lilac` slash command 最多帶 24 個 custom-command options（`discord-adapter.ts` 的 `customOptions.slice(0, 24)`） |

## 更新本文件

- Upstream contract gaps：`apps/core/src/tools/question.ts`、`apps/core/src/surface/bridge/request-composition/checkpoint-selection.ts`、`apps/core/src/tool-server/create-tool-server.ts` 的 `resolveSafetyMode`、`apps/core/src/conversation/thread-store.ts` 的 Discord 分支，以及 `apps/core/src/tool-server/tools/surface.ts` 的 enrichment 呼叫。若 upstream 把其中一項改成平台中立，該列就變成「尚未實作」或應移除。

- Telegram 行為：`cd apps/core && bun test tests/surface/telegram/` 覆蓋 router（`telegram-request-router.test.ts`）、outbox、polling supervision，以及對 fake Bot API server 的 adapter 測試。
